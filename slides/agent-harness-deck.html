Act 1 · 调研 — 定义与共识

什么是 Agent Harness

模型之外的一切：系统提示、工具、循环、上下文管理、安全护栏——让 LLM 真正干活的工程外壳。
01定义与边界

harness = 包住模型的基础设施层：system prompt、工具协议、agent loop、上下文管理、安全、持久化。模型同质化后，产品差异化集中在 harness——「2025 是 agent 之年，2026 是 harness 之年」（Zylos）。

02控制面视角

harness 是 AI 的 control plane（Medium 2026）：工具编排、验证回路、记忆、护栏都在这层。下一个瓶颈正转向环境工程——为 agent 重构企业 API 与系统，而不是继续卷外壳。

03工程实践视角

Augment Code 的拆解：harness 工程 = 约束（规则文件 / 护栏）+ 反馈回路（plan-execute-verify）+ 质量门禁。结论一致：可靠性来自验证闭环，不来自模型本身。

04我的学习路径

三步走：读文献建地图 → 手撕最小内核 → 精读生产源码验证动机——对应后三幕。判据：能讲清「它刻意不做什么」，才算读懂一个 harness。

Act 1 · 调研 — Anthropic · Building Effective Agents · 循环

Agent 的极简定义：循环中自主用工具

"Agents … LLMs autonomously using tools in a loop."Anthropic Engineering · 2024-12 · 与 dozens of teams 的共建经验
01

Workflows vs Agents：workflow 用代码预先编排 LLM 步骤（确定性、可预测）；agent 让模型自己决定下一步（动态、可扩展）。判据：无法预先写出步骤图的场景才用 agent——从简原则。

02

augmented LLM 是最小单元：检索 + 工具 + 记忆增强的单次调用；agent = 把它放进 while 循环。复合模式都是循环之上的编排：routing（分流）、prompt chaining（串行）、orchestrator-workers（动态分解的默认模式）、evaluator-optimizer（生成-评审环）。

03

反模式警告：为炫技上多 agent 框架、把业务逻辑硬编码进提示词——通常一个 augmented LLM 循环就够；框架的抽象税常常大于收益。

04

教学直译：pi-from-scratch 的 runAgent 就是这个定义的直译——while + tool_call 分发 + 停止条件，~200 行没有更多魔法；第二幕 P10 逐分支拆解。

05

趋势：模型越强，可托付的自主度越高、人写的编排越少——"letting intelligent models act intelligently"；harness 的工作从「教模型做事」转向「给模型好环境」。

Act 1 · 调研 — Anthropic · Context Engineering · 预算

上下文是有限资源

"Find the smallest set of high-signal tokens that maximize the likelihood of your desired outcome."
01

Context rot（实证现象）：needle-in-a-haystack 类研究表明 token 越多召回越差——渐退不是断崖。根因：transformer 的 n² 两两注意力被拉薄 + 训练分布偏短序列、长程依赖参数少。

02

推论：注意力预算——每个新 token 都在花预算，所以「最小 ≠ 最短」：要的是信息密度。这句话是整个上下文管理（压缩 / 披露 / 剪枝）的第一性根据。

03

系统提示的「正确海拔」：两端都是坑——过度硬编码 if-else 脆弱难维护；过度抽象含糊则没有信号。正解：section 化 + 固定顺序（XML/Markdown 分节），从最小提示开始按失败模式增量补。

04

工具也是上下文：少而正交、返回 token 高效——人都分不清该用哪个工具时，模型更分不清；few-shot 要精选多样正例，不要往提示里塞边界情况清单。

05

Just-in-time 检索：不预取全部，只留轻量标识符（路径 / 存好的查询 / 链接），运行时用工具按需加载；metadata 即信号（文件名、目录层级、时间戳都在暗示用途）。Claude Code 混合模式：CLAUDE.md 前置 + glob/grep 自主探索——像人类用文件系统，而非背下全书。

Act 1 · 调研 — 长程任务的三个杠杆 · 预算

超长任务的三板斧

LEVER 1
Compaction 摘要重启

是什么：临近窗口上限时摘要并重启新窗口。
代表：Claude Code 保留架构决策 / 未解 bug + 最近 5 个文件；最轻形式 tool result clearing——老的工具原始输出没必要留。
适用：多轮对话、需要连贯叙事。
我的对应：compactContext（P12）。

LEVER 2
Structured Notes 结构化笔记

是什么：agent 定期把状态写到窗口外，需要时读回。
代表：Claude 玩宝可梦——数千步精确记账、探索地图、战后总结，上下文重置后靠自己的笔记续命。
适用：里程碑清晰的迭代开发。
我的对应：todo_write（P13）。

LEVER 3
Sub-agents 子代理

是什么：主 agent 出计划，子 agent 各带干净窗口深挖。
代表：Anthropic 多 agent 研究系统——每个子 agent 耗数万 token，回来只交 1–2k token 摘要，复杂研究任务大幅超越单 agent。
适用：可并行的探索 / 检索。
我的对应：P6 编排层（规划中）。

三者不互斥：压缩管叙事 · 笔记管状态 · 子代理管注意力 选型取决于任务形态（Anthropic） 第三幕会看到它们被制度化的样子

Skills：渐进披露的技能库

LEVEL 1
metadata 常驻

SKILL.md frontmatter 的 name + description 启动即进系统提示——只够判断「何时该用」，不足以指导干活。目录 = 一本书的目录页。

LEVEL 2
正文按需加载

模型判断任务匹配后，用工具读入完整指令——Voyager 技能库「按需检索」的直接继承；正文进上下文，不匹配就一个字不花。

LEVEL 3
附加文件再用再读

正文引用 reference.md / forms.md 等资源，用到才读；配合代码执行，脚本不进上下文也能被运行 → 技能容量无界。

01

本质是上下文管理：skills 不改模型、不加连接，纯粹是「该进上下文时才进」——三级披露 = 对「最小高信号集」的工程化。2025-12 成为开放标准（agentskills.io），跨 20+ agent 通用。

02

与 MCP 互补：MCP 给连接（有什么工具），Skills 给工作流知识（怎么组合着用）；安全上只装可信来源、审计捆绑代码。

03

我们的同构实现：目录常驻 + load_skill 按需加载 <skill_content>——P14；未来：agent 自己写 skill（Voyager 终身学习的回归）。

Act 2 · 实践 — 核心机制 · 循环

Agent Loop：一次完整的生命

① 用户输入

tui prompt 进 context.messages（user）

↓每轮开始
② 组装请求

system + tools + messages → StreamFn 流式调用（重试退避兜底）

↓
③ 流式解析

SSE 四事件：text_delta / tool_call / done / error——错误编码进事件流，不抛异常

↓
④ 分支判断

stop_reason：tool_use → 右侧执行；否则走停止条件

↓
⑤ 回填续轮

tool_result 回填（必须配对）→ 回到 ②，直到模型不再调工具

⚙ 工具执行子流程（tool_use 时）

beforeToolCall 拦截（.env/.ssh/id_rsa）→ needsApproval 用户审批 → 执行（withTimeout：read 10s / grep 15s）→ afterToolCall 脱敏（sk-***）→ 结果回填。同消息多 tool_call 并行执行。

▣ 压缩检查（每轮末）

tokens > 0.8 × 窗口？→ compactContext 摘要压缩，保留 system + 摘要 + 最近对话。失败保留原文；abort 不压缩（P12 红线）。

■ 停止条件（四种出口）

end_turn 正常收工 · max_tokens 截断 · aborted 中断——补 error 结果保配对 · error 重试后仍失败；detectLoop：连续 3 次同指纹强停。

每轮不变量：配对必须完整 · 估算不超预算 · 失败编码进事件流 边界比循环重要：四条停止路径 + 两处红线全在 ~200 行 agent.ts
Act 2 · 实践 — 上下文管理 一 · 预算

Token 预算与安全切点

01

估算：chars / 4 近似 token（中英混合误差教学可接受）；contextWindow 进配置不写死——预算意识从「知道自己还剩多少」开始。

02

两层防线：轻度超限 → 找 cut point 裁剪旧轮次；重度超限 → 触发摘要压缩（下一页）。对照文献：Anthropic 把 compaction 列为上下文工程第一杠杆。

03

cut point 三规则：必须是消息边界；不能切断 tool_call / tool_result 配对（切断 = 恢复后 API 400，session 直接不可用）；尽量按完整轮次（split turn）对齐，避免半截对话。

04

为什么难：API 只认「每个 tool_call 都有 tool_result」，而 token 计数在变、消息在流式追加——安全切点是运行时计算，不是静态配置。

05

取舍：精确 tokenizer = 依赖 + 复杂度；估算误差由 0.8 阈值的提前量吸收——这是教学版对「最小高信号集」的务实解，也是 deepseek 上 tokenMeter 的简化版。

Act 2 · 实践 — 上下文管理 二 · 预算

压缩的安全纪律

压缩是安全工程，不只是摘要——失败时的行为比成功时更重要。
01

流程：compactContext 把旧消息交给 LLM 摘要成一条 summary 消息，保留 system + 摘要 + 最近对话，循环继续；压缩前后都做 token 复测。

02

红线一：失败不替换。压缩出错 → 保留原始 context。空摘要比没有摘要更危险——宁可用满窗口，也不要突然失忆；这是「保留原文比坏摘要安全」的保守设计。

03

红线二：abort 不压缩。中断时刻的上下文半新不旧，此时压缩最容易产出损坏的摘要；宁可什么都不做，把一致性留给下一次。

04

文献回响（Anthropic）：压缩的艺术在「保什么 vs 丢什么」——先最大召回再修剪精度；最安全的轻量形式是 tool result clearing（深层的原始工具输出没必要重看）。

05

生产级长什么样（deepseek，P16）：头锚定（失效点最晚）+ 尾部按 retainRatio 保留 + 配对边界 in-progress=0 才可切；摘要调用逐字重放 system+tools+被压缩区——复用 KV 前缀缓存；摘要 ≥ 原文则拒绝压缩；超长工具结果先 prune（头 4096 + 尾 1024，中间打标记）。

Act 2 · 实践 — 工具系统 · 工具 + 护栏

工具契约与四道防线

01

契约：AgentTool = name + description + zod inputSchema + execute + timeoutMs / needsApproval。schema 校验失败返回结构化错误（哪个字段、什么类型）——模型据此自我纠正，这正是 SWE-agent「护栏 + 反馈」原则的最小实现。

02

执行：同一消息多个 tool_call 并行执行；withTimeout 用 Promise.race 兜底——read 10s / grep 15s / bash 30s，不让单个工具卡死整个循环（教学版不真取消，超时替换结果为错误）。

03

四道防线：needsApproval 用户审批（rm 等危险操作，y/n）→ beforeToolCall 通用拦截（.env / .ssh / id_rsa 直接 block）→ afterToolCall 结果脱敏（sk-*** 打码）→ detectLoop 死循环检测（最近 3 次调用同指纹即停）。

04

为什么钩子是参数不是 if-else：拦截与脱敏由拼装层注入（cli.ts 传函数），agent 核心只约定调用时机——策略与机制分离，是第三幕「引导与执法分离」的前奏。

05

todo_write 的奥义：无状态整表替换（○ ▶ ✓ ✗）——任务进度外置到工具结果里，最新清单永远是最后一次 tool call 参数，天然贴在上下文尾部、永远新鲜、零重注入（文献：structured note-taking；deepseek 把这一点讲透了）。

Act 2 · 实践 — 生态扩展 · 插座

MCP 与 Skills：能力从哪来

01

MCP（接工具）：手写零依赖 JSON-RPC client——spawn 子进程 stdio 通信，initialize 握手 → tools/list 发现 → tools/call 调用；MCP 工具适配成普通 AgentTool（schema 直转），server 连不上只警告不阻塞启动。

02

Skills（给知识）：目录（name + description）常驻 system prompt；模型判断匹配后调 load_skill 加载 <skill_content> 完整指令——P8 三级披露的同构实现；引导语明确「目录只有摘要，未加载前不要推断指令」（防幻觉）。

03

一次真实迭代（v1 → v2）：v1 关键词匹配的三缺陷——字面匹配漏激活（「帮我看看这段代码」不含「审查」）、trigger 枚举不完、逐轮激活指令淡出。v2 改模型语义路由：不怕换说法、加载结果留在 messages 里后续轮次免重载、压缩丢了指令可重新 load（自愈）。

04

代价与取舍：激活多一次工具往返；弱模型可能漏激活 / 过度激活（关键词版是确定性的）；目录每轮占少量 token——用少量常驻 token 换按需的无限容量，正是渐进披露的交易结构。

05

边界与未来：MCP 管连接（有什么工具），Skills 管工作流（怎么组合）——与 Anthropic 定位一致；skill 还可捆绑确定性脚本（不进上下文直接执行），以及让 agent 自己沉淀 skill（Voyager 回归）。

Act 2 · 实践 — 工程地基 · 制度的雏形

让它能被信任的地基

01

StreamFn 注入：stream 函数作为参数传给 runAgent / compactContext（默认 OpenAI 兼容实现）。切 Anthropic 后端时 agent 核心一行不改；契约：失败不 throw，编码进事件流（error 事件）——上层统一处理。

02

消息格式适配：contextToAnthropicMessages——tool 结果打包成 user 消息的 tool_result block（Anthropic 无独立 tool role）、system 独立字段、max_tokens 必填、stop_reason 双向映射（tool_use / end_turn / max_tokens）。

03

重试退避：retryableFetch 对 429 / 5xx 指数退避——LLM API 的瞬态失败是常态不是异常；与 pi / deepseek 两个参考项目对齐。

04

持久化容错：session.jsonl 逐行解析、跳过损坏行（进程崩溃可能写出半行 JSON——丢弃单行好过丢弃全部历史）；恢复时校验配对、补 error 结果。

05

配置与验证：优先级 env > config.json > 默认值，密钥只走环境变量不落盘；100 个单元测试全绿——skills / 上下文管理全部纯函数，让「手撕」可回归、可教学。

Log 唯一权威，万物皆折叠

事件溯源：log 是 append-only 的唯一真相；「当前状态」全部是 fold 出来的投影——没有第二份真相。
01

surface 投影：模型看到的消息序列 = 确定性 fold。surfaceOp 只有 append 与 replace 两种；压缩的「删除」其实是替换投影——log 永不删，resume / fork / 审计全部免费；内存只放「还没取得写入资格的 pending」。

02

替换的严格校验：replace 带 provenance / 范围校验——tool 配对不悬空、replaceGeneration 失效派生缓存；教学版的「配对安全」在这里被制度化。

03

压缩管线（全貌）：三触发（压力 0.8×窗口 / 溢出 retry / 手动 idle）→ 先 prune 再重测，仍超才 compact；选区头锚定 + 尾部 retainRatio、配对边界 in-progress=0；摘要调用逐字重放前缀吃自己的 KV 缓存，摘要 ≥ 原文拒绝。

04

记忆也是 fold：情景 = session log；整固 = compaction；声明性 = AGENTS.md 链（SHA-1 去重）；程序性 = skills 目录；跨会话 = @提及冻结快照。刻意不用向量检索——用「可寻址」（名字 / 路径 / @）换可信、可审计。

05

为什么这是根基：请求由 log 派生 → 每步请求 = 上一步前缀 + 新后缀——下一页的前缀纪律正源于此；一切机制（plan 状态、todo、目录）都是「往 log 写的人」或「从 log fold 的人」。

Act 3 · 深读 — KV cache 与行为设计 · 制度

追加优先，失效最晚

01

前缀稳定性纪律：harness 不实现缓存（缓存在 provider 侧），实现的是「不许动前缀、只许追加后缀」——系统提示 section 化 + 固定 order、工具 schema 稳定（plan 模式不装卸工具正为此）、request/header 去重。

02

失效不可避免时（压缩、plan 切换）：把失效点推到最晚（压缩头锚定），并让引发替换的调用自己重放失效点之前的内容——换摘要的请求复用自己的缓存。缓存失效是「算力账单」，不是内容变化。

03

制度化：每个包 README 必须写 Model Experience 三段（模型看到什么 / token 效应 / KV cache 效应），脚本强制；所有请求分四类：append-only / stable prefix / replacement / independent。把纪律变成流程。

04

引导与执法分离：模型行为靠 context 内容引导（提示 section / 工具描述 / 消息）；安全靠 sandbox / approval 独立执法，互不读写。运行时是 context 的策展人，不是监工——刻意不做「计划执行监督器」。

05

四阶段接力（plan 案例）：规划期常驻 section → 交接——计划全文 + 执行指令都是模型自己写的 tool 参数 / 结果 → 执行期靠历史（前缀一字不变）→ 长程被压缩稀释后靠 todo_write 兜底。引导即上下文本身。

Act 4 · 心得 — 设计哲学

贯穿全部答疑的三条哲学

哲学 1
Log 唯一权威

陈述：真相只有一份，视图都是 fold；内存只放「还没取得写入资格的 pending」。
机制：skills 目录、plan 状态、todo、记忆——全是「往 log 写的人」或「从 log fold 的人」。
影子：session.jsonl 逐行容错；skill 加载结果留在对话里，不另设状态。

哲学 2
追加优先，失效最晚

陈述：能 append 就不 rewrite；必须动前缀时，让引发替换的调用自己吃回缓存。
机制：目录「追加式替换」、request/header 去重、压缩头锚定 + 摘要重放。
影子：估算只增不改写历史；压缩失败保留原文（宁可不动）。

哲学 3
引导与执法分离

陈述：判断力留在模型（它是路由器），机制做成工具（稳定、可记账）；安全独立执法。
机制：一切能力皆 tool——schema / 信封 / 日志 / 调度免费继承；sandbox / approval 不读引导。
影子：load_skill 是工具不是 if-else；审批与提示词互不越界。

三条其实是同一条：把「状态」和「行为」都赶到可审计的机制里，模型只负责判断
Act 4 · 心得 — 学习心得

手撕一圈，验证了什么

01

文献的「应然」基本都验到了：agent = loop（runAgent 直译）；渐进披露有效（skills v2 明显优于关键词 v1）；工具护栏换来自纠（schema 错误回喂模型）；压缩是安全工程而不只是摘要（两条红线的由来）。

02

最有价值的意外：文献一句带过的话，手撕时才懂分量——「tool result clearing 最轻」背后是配对红线；「smallest high-signal set」背后是 cut point 不能切配对；「循环」二字背后是四条停止路径的边界工程。

03

读生产源码的正确姿势：设计动机藏在「它刻意不做什么」里——deepseek 刻意不用向量检索（可信可审计优先）、不做计划监督器（引导即上下文）、把一切做成 tool（模型是路由器，工具是手）；不做什么比做了什么更诚实。

04

方法论沉淀：先文献后代码（带着问题读源码，动机才浮现）；边讲边写（每个功能先对齐方案再动手）；答疑日志 = 把「当时为什么这么定」固化成可复习的资产。

05

下一步（P6 编排层）：subagent = 普通 Agent + Session（seam 只写编排不写引擎）；workflow 是 subagent 的上层——把编排从模型脑子里搬进确定性脚本（agent() / parallel() / pipeline()）；配 worktree 隔离与分屏。
